# 공무원 한글문서 편집스킬 (HWPX)

부르는 이름(호출명): `/gongyong-hwpx`

견본 한글 파일의 문단을 **복사해서 글만 바꿔 끼운다.** 그래서 여백·글꼴·간격·표 모양이 견본과 같다.
견본에 없는 글꼴·크기·색은 만들지 않는다. 대신 사용자 원칙에 따라 **자간·줄 간격·다음 문단과 함께·칸 너비**는 도구가 조정한다.

| 쓰는 것 | 하는 일 |
|---|---|
| `scripts/analyze.py` | 견본의 **여백**과 문단마다 번호·역할·서식·글을 보인다(양식 지도) |
| `scripts/build.py` | 계획 파일대로 만들고, 자동 맞춤·검사까지 한다 |
| `scripts/check.py` | 만든(또는 사용자가 고친) 파일의 구조만 검사한다 |
| `assets/basic_report.hwpx` | 견본이 없을 때 쓰는 기본 양식 — 번호표 `references/basic-report-map.md` |
| `references/style-guide.md` | **사용자의 문체·짜임·표기·용어·배치 원칙.** 글을 쓰기 전에 반드시 읽는다 |
| `references/plan-format.md` | 계획 파일 규칙 전부 |
| `references/table-rules.md` | 표·도표·사진 규칙(표를 넣을 때 읽는다) |

- 파이썬과 lxml이 필요하다. 없으면 `pip install lxml`.
- `references/auto-fit.md`: 도구가 저절로 맞추는 규칙의 자세한 설명(알림 뜻이 궁금할 때만)
- 경로는 이 스킬 폴더 기준이다(예: `python <스킬폴더>/scripts/analyze.py …`). 파일 경로 `/mnt/user-data/…`는 Claude 앱 기준이고, 다른 앱에서는 그 앱의 올린 파일·결과 폴더를 쓴다.
- **파이썬을 돌릴 수 없는 앱**(코드 실행이 꺼진 ChatGPT·Gemini 등)에서는 한글 파일을 만들지 못한다. 그때는 `references/style-guide.md`대로 글을 기호(□ ○ - · ※)째 써 주고, 사람이 한글에 붙여 넣게 안내한다(한글 파일 만들기·자동 맞춤은 파이썬이 되는 곳에서만). 이때도 글 끝에 여백 안내를 빠짐없이 적는다: "기본 양식 여백은 A4, 본문 칸 사방 20mm입니다. 온나라 공문에 붙여 넣으실 때는 [쪽] → [편집 용지]에서 왼쪽·오른쪽 여백을 20·20mm로 맞춰 주세요."(6절)

## 1. 견본 정하기

- 사용자가 `.hwpx`를 올렸으면 그것이 견본이다.
- `.hwp`(옛 형식)만 있으면 읽을 수 없다. "한글에서 [파일]→[다른 이름으로 저장]→파일 형식 'HWPX'로 저장해 올려 주세요"라고 부탁한다.
- 견본이 없으면 `assets/basic_report.hwpx`를 쓴다. 2절 대신 `references/basic-report-map.md`를 본다.
- **사용자가 결과 파일을 고쳐서 다시 올리면 그 파일이 새 견본이다.** 고친 것을 되돌리지 않는다. 무엇을 왜 고쳤는지 먼저 살펴 다음 문서에도 반영한다.
- 견본 파일에 덮어쓰지 않는다. 결과는 늘 새 이름으로 만든다.

## 2. 양식 읽기 — 여백 먼저

```
python scripts/analyze.py 견본.hwpx          # 양식 지도(맨 위가 '여백 먼저')
python scripts/analyze.py 견본.hwpx --text   # 글만 처음부터 끝까지
```

1. **여백 먼저**: 본문 폭·높이, 문단 왼쪽 여백·내어쓰기, 표 폭이 본문과 맞는지(끝선 맞음 / 튀어나옴)를 본다. 글과 표가 이 안에 들어가야 깔끔한 문서가 된다.
2. **문단 목록**: `[번호]`가 계획 파일의 `like` 값이다. 역할(장 제목·큰 항목(□)·중간 항목(○)·작은 항목(-)·주석(*)·참고(※)·표·빈 줄·참고 머리표)은 기호와 정렬로 짐작한 것이니 글과 서식을 보고 확인한다.
3. `조각N cX …`: 한 문단 안의 글 조각과 그 모양(굵은 이름표, 위 첨자 * 등).
4. `--text`로 글을 읽고 **견본의 글버릇**(끝맺음·기호 앞뒤 빈칸·날짜·단위·괄호 이름표)을 그대로 따른다.

## 3. 내용 정리 — style-guide.md를 따른다

- `references/style-guide.md`를 읽고 짜임·문장·표기·낱말을 맞춘다. 글꼴은 **HY헤드라인M·휴먼명조·맑은 고딕 세 가지뿐**(견본이 없을 때). 모범 짜임은 style-guide.md 2절이다.
  - 장마다 첫 줄은 결론 한 문장, 개조식 명사형 끝맺음(~함·~임·~됨 — `~으로`로 끝내지 않고 `~으로 편성`처럼 할 일을 붙임), 굵은 이름표 + 쌍점, 결론은 ⇒, 표 아래 ※, 기한은 `— ’26. 12. 18.(금)까지`.
  - 로마자 장(Ⅰ.·Ⅱ.)은 긴 계획서에서만. 본문 2~3쪽(참고 포함 4쪽 안팎)이면 요약 상자 다음 바로 □부터 쓴다.
  - **요약 상자**(제목 상자 아래 첫 상자)는 **한 문장으로 두세 줄**만, 끝맺음은 **`~하고자 함`** 또는 **`~에 대한 보고임`** — 번호(①②)·여러 항목을 넣지 않는다(세부는 아래 □·○로, 도구가 알림).
  - **올림글자(위 첨자)를 적절히**: 낯선 낱말 뒤 `^^*^^` + 아래 `*` 풀이 줄(○ 아래는 8번, - 아래는 11번), 긴 정식 이름은 줄임말 뒤에 위 첨자로(`AI 기본법^^인공지능 발전과 신뢰 기반 조성 등에 관한 기본법^^`). 한 쪽에 두세 개 정도 — 많으면 읽기 어렵다. 근거법령·참고1처럼 정식 이름을 밝혀야 하는 곳은 줄이지 않는다.
  - **표지**가 필요하면(여러 쪽 계획서·보고서) 기본 양식 19~23번: 시 슬로건 → 제목 띠 → 가운데 개요 상자(□·○로 구성, 높이는 글에 맞춤) → 대구시 마크 → 부서명. 자리는 도구가 맞추고 본문은 새 쪽, 쪽 번호는 본문부터 1(`references/basic-report-map.md` 표지 절).
  - **작대기(-) 위주로 쓴다**(위계 □ → ○ → -는 지킴): ○는 줄여 묶음의 요지 한 줄로 두고, 세부는 그 아래 -로 나눈다. ○ 아래에 -를 붙이면 **둘 이상**(하나뿐이면 ○ 글에 합침 — 도구가 알림).
  - 본문에서 참고를 `(참고1)`처럼 가리키지 않는다. 참고는 뒤쪽 참고 머리표로만 둔다. 참고 머리표 아래에 ○ 한 줄 설명을 두지 않는다(설명은 표 아래 ※ — 도구가 알림).
  - **표·도표·사진**: `references/table-rules.md`를 따른다(표 글씨·정렬·`· 항목`·열 합치기·기준/단위 줄·사진은 칸 배경·도표는 투명 선 표 `flow`·참고 쪽 채우기). 표를 하나라도 넣을 때 읽는다.
  - 부연설명 괄호(괄호와 그 안 글)는 2pt 작게 — 도구가 저절로 함. 줄임말 뒤 원래 이름은 괄호 없이 **위 첨자**로 바로 붙인다(`유가보조금^^유류세연동보조금^^`). 낱말 풀이는 위 첨자 `^^*^^` + 아래 `*` 설명 줄.
  - **근거법령은 무조건 1번**(모든 공문·보고서·계획서에 근거법령이 옴): 로마자 장이 있는 계획서는 **Ⅰ. 근거법령** 장 아래 ○로 법령·규칙·계획을 하나씩(□ 없이 ○ 바로 — 대구시 「…개최 계획」의 Ⅰ 추진근거 꼴), 개요는 Ⅱ.부터. 로마자 장이 없으면 **첫 □가 □ 근거법령**(아래 ○로 법령·규칙·계획을 하나씩 — 사용자 원칙 2026-11-03). **근거법령도 ○ 둘 이상**(항목 수 원칙 그대로 — 사용자 원칙 2026-11-03): 하나뿐이면 같은 법령의 시행령·시행규칙, 관련 조례, 훈령·예규·고시·지침, 계획 가운데 확인된 것을 더한다(같은 법령의 여러 조는 한 ○에 `제7조제2항·제41조제2항제2호`). 다른 □ 안에 `○ **(추진근거)**`로 넣지 않는다. 표지가 있으면 개요 상자의 첫 ○도 근거. 뒤에 쓰면 도구가 맨 앞으로 옮기고(장째·□째), 다른 □ 안의 ○ (추진근거)는 □ 근거법령으로 떼어 첫 □로 세우며(아래 - 줄이 모두 법령이면 ○로 올림), 없으면 알린다.
  - **근거를 지어내지 않는다.** 법령 검색 도구로 이름과 조문을 확인한 법령만 쓴다 — 훈령·예규·고시·지침은 법령 검색에 안 잡히면 행정규칙 검색으로 찾는다(차례는 법률 → 시행령 → 시행규칙 → 조례 → 규칙 → 훈령·지침 → 계획·공문). 확인 못 하면 `「○○법」 제○조`로 비워 두고 전달할 때 알리며, 사용자가 말한 내부 계획·공문 이름은 그대로 쓴다. '근거법령 없음' 알림을 없애려고 그럴듯한 법령을 넣는 것은 금지.
  - **참고1은 근거법령 조문 발췌**: 법령 검색 도구로 **원문을 확인한 조문만** 그대로 옮긴다(글자 하나 바꾸지 않음, 필요한 항만 골라 발췌). 법령마다 제목 걸친 상자(16번)에 `<법령 이름>`을 제목으로, 조문 사이는 빈 줄, 아래 `※ 출처 : 국가법령정보센터(기준일 현행 …)`. 그 밖의 참고는 참고2부터.
  - **제목 걸친 상자**(기본 양식 `like 16`: 위 선 가운데에 `<관 련 법 령>` 같은 제목이 걸친 상자)는 자주 쓰는 상자 모양이다 — 관련 법령 전용이 아니고, 묶어 보일 내용이 있을 때만 쓴다.
  - **항목 수는 셋쯤**(사람은 셋으로 정리하는 것을 좋아함): □ 아래 ○, ○ 아래 -, - 아래 ·는 3개쯤, **2~5개를 벗어나지 않게**. □ 아래 ○가 하나뿐이면 `**(추진방향)**` → `**(주요내용)**` → 표 꼴로 나눈다. 위계는 □ → ○ → - → ·(작대기 다음은 가운데점, 기본 양식 24번) — 도구가 벗어난 곳을 알림.
- **사실·숫자·이름은 사용자가 준 것만 쓴다.** 모르는 값은 `○○`·`○○○원` 같은 자리표시로 두고 전달할 때 알린다.
- 꼭 필요한데 빠진 것(제목, 보고 날짜, 부서)은 짧게 한 번에 묻는다. 내용이 분명하면 묻지 말고 바로 만든다. 날짜·부서를 모른 채 만들면 그 줄을 빼지 말고 ○로 채운다(`’26. ○. ○.(○)	○○○○과 ○○○` — 빠지면 도구가 '고쳐야 함').
- **내용이 거의 없으면 질문으로 모은다(근거법령부터).** 한 번에 한 주제만, 번호 선택지로 묻고 고른 번호를 받는다(사용자가 고치면 그대로 따름).
  - 차례: 근거법령 → 추진배경 → 현황 → 주요내용 → 확산·운영 → 일정 → 예산 → 기대효과 → 행정사항·날짜·부서
  - 근거법령은 법령 검색 도구로 **원문 조문을 확인한 것만** 후보로 낸다(조문 번호·요지). 확인 못 한 법령은 내지 않는다.
  - 선택지는 사실을 지어내지 않는다. 숫자·기관 사정처럼 확인할 수 없는 것은 "맞을 때만 고르라"고 밝히고, 답이 없으면 ○○로 비운다("동그라미로 공란").
  - 답은 작업 폴더의 기록 파일에 차례로 적어 둔다(대화가 길어져도 이어 쓰게).
- 한 항목은 한 줄이 원칙이다. 한 줄 글자 수는 대략 `쓸 수 있는 폭(mm) ÷ (글자 크기(pt) × 0.353)`이다(기본 양식 ○ 14pt ≈ 32자, - 13pt ≈ 33자).
- 견본 속 예시 문장·사람 이름·연락처는 결과에 옮기지 않는다.

## 4. 계획 파일 쓰기

블록 하나가 결과 문서의 문단(또는 표) 하나다. 자세한 규칙은 `references/plan-format.md`.

```json
{"title": "공원 안내판 정비 계획(안)",
 "blocks": [
  {"like": 0, "text": "공원 안내판 정비 계획(안)"},
  {"like": 6, "text": "추진배경"},
  {"like": 7, "text": "**(현황)** 노후 시설이 29곳^^*^^으로 야간 시인성이 떨어짐"},
  {"like": 8, "text": "노후 시설: 설치 후 10년이 지난 안내판"},
  {"like": 14, "table": [["구  분", "현  행"], ["표지판", "일반 도색"]]}
 ]}
```

- `like`: 모양을 빌릴 견본 문단 번호. `{"like": N}`만 쓰면 그 문단을 그대로 복사(빈 줄 등).
- `text`: 넣을 글. 머리 기호(`□ `, `  ○ ` 등)는 도구가 견본 것을 붙인다.
- `**…**` 굵은 조각, `^^…^^` 위 첨자 조각(견본 문단에 그 모양 조각이 있을 때) — 위 첨자는 낱말 풀이 `*`와 줄임말 뒤 원래 이름(`유가보조금^^유류세연동보조금^^`)에 쓴다.
- 표: `table`(줄 목록, 첫 줄은 제목 줄, 줄·칸 수 자유) 또는 `cells`(`"줄,칸"`으로 칸만), 도표는 `flow`(상자 글 목록) + 위 제목 `title`. 표 위 기준·단위 줄은 `"unit": "(단위 : 백만원)"`.
- `\n` 줄 바꿈, `⎵` 고정폭 빈칸(**1/4 글자**), `⍽` 묶음 빈칸, `\t` 탭. `page_break: true`는 새 쪽.

## 5. 만들고 검사하기

```
python scripts/build.py --template 견본.hwpx --plan plan.json --out 결과.hwpx
```

도구가 저절로 하는 일(사용자 원칙 — 자세한 규칙은 `references/auto-fit.md`, 끄려면 plan-format.md의 옵션):
- 글: 네 글자 제목·이름표 붙여 쓰기, 번호 매기기(Ⅰ.·1.·가.), □ 사이 빈 줄, 쌍점 앞뒤 한 칸, 이름표·쌍점 뒤 내어쓰기, 괄호 이름표 네 글자·작대기 항목명 세 글자 폭 맞추기, 숫자 꾸밈말 묶기, 부연설명 괄호 2pt 작게, *·※ 설명은 2pt 작게(아래 3pt 띄움), 따옴표·낫표·가운데점 붙이기, 줄 첫머리 낫표(「) 반 칸 당기기(아랫줄과 끝선 맞춤), 단어 단위 줄 바꿈
- 표: 끝선 맞춤, 칸 너비·글자 크기(12→10pt)·한 줄로 입력·줄 균형, 옆 열 폭 빌리기·뜻 단위 줄 바꿈·칸 여백, 금액 오른쪽·숫자 가운데·`· 항목` 왼쪽, 기준·단위 줄, 표 아래 ※·* 모양·간격·표 글자보다 1pt 작게, 제목 걸친 상자의 제목 칸 넓히기·안 글 왼쪽 정렬
- 쪽: 줄 맞춤(자간 -18%~+5%, 끝 줄 한 낱말은 올려 보고 안 되면 7~10자 내리기, 화살표 뒤 내용이 갈라지면 화살표째 내리기·안 되면 화살표 뒤 글자 밑에 맞추기), 끝선이 애매한 쪽은 줄 간격 통째로 넓히기, ○ 묶음·□ 블록 한 쪽에, 쪽 맞춤(줄 간격·빈 줄), 빈 쪽 채우기, 참고 쪽 꽉 채우기(작은 표 둘을 한 장에), 표지 자리 잡기와 쪽 번호, 제목 상자를 쪽 맨 위에 붙이기(위 빈 공간 없음)
- 차례: 근거법령을 1번으로 옮기기(Ⅰ. 장·첫 □·표지 개요 상자), 다른 □ 안의 ○ (추진근거)를 □ 근거법령으로 떼어 첫 □로

읽을 것(출력은 두 등급):
- **## 고쳐야 함** — 전하기 전에 계획을 고쳐 다시 만든다: 근거법령 없음, ‘~으로’로 끝나는 줄, 한 열에 세 가지 정보, 요약 상자에 번호·여러 항목·끝맺음, 끝 줄에 한두 낱말만 남은 문단(글을 조금 줄이거나 순서를 바꿈), ○·-·· 항목 수(하나뿐·다섯 넘음), 두 쪽에 걸친 □ 묶음, 칸보다 긴 낱말(글자 단위로 끊김), 줄여도 넘어가는 칸(칸 글 줄이기·칸 합치기), 빈칸이 크게 벌어지는 줄, 견본 기호와 글 기호가 다름·굵은 조각 없음(대개 `like`를 잘못 고른 것), 검사 결과 '문제 있음'·'좁은 칸'(표가 튀어나옴).
- **낱말 하나 덜기·더하기(줄 맞춤)**: '한 줄 줄이기 후보'(약 N자)가 나오면 그 문단에서 **없어도 되는 낱말 하나**를 빼고 다시 만든다 — 조사(을·를·의·와), 위 이름표·제목이 이미 말해 주는 말, 꾸밈말, `와` → `·`. 알림의 N자는 자간을 최대로 줄인 기준이라 한두 자 더 빼면 덜 빽빽하다. 뜻·숫자·날짜·이름·법령은 건드리지 않는다. 반대로 줄이 휑하거나 쪽이 비면 뜻을 바꾸지 않는 낱말이나 줄 하나를 더할 수 있다(사실은 지어내지 않음). 사람은 문맥으로 이해하므로, 줄을 내려 윗줄을 휑하게 두는 것보다 낱말 하나를 빼는 편이 낫다.
- **## 알림(참고)** — 도구가 한 일의 기록. 읽고 넘어간다. 어림 쪽 수와 쪽마다 채운 비율은 꼭 본다: 마지막 쪽이 거의 비었거나 쪽 수가 예상과 다르면 내용을 줄이거나 나눈다. **'순서 바꾸기를 검토하세요'**가 나오면, 뜻·흐름이 그대로일 때만 계획에서 두 □ 묶음 순서를 바꿔 다시 만든다(쪽을 꽉 채우려면 순서를 바꿔도 된다는 사용자 허락).
- Claude 앱에서는 결과를 `/mnt/user-data/outputs/`에 두고, 파일 이름은 문서 제목으로 짓는다.
- **글 차례**를 처음부터 끝까지 읽어 빠진 내용·오탈자·자리표시를 확인한다.
- 이 도구는 한글 없이 줄·쪽을 어림한다(한글 2024로 맞춰 본 결과 시험 문서 4개·71문단의 줄 바꿈과 쪽 수가 모두 같았다). 표에 없는 글꼴은 어림값이라 덜 정확하다. 마지막 확인은 한글에서 한다.

## 6. 전달하기

- 결과 파일을 건네고 쉬운 말로 3줄 안팎만 적는다: 어떤 양식으로 만들었는지, 자동으로 맞춘 것, 채워야 할 자리표시, "한글에서 열어 보시고 고칠 곳을 말씀하시거나 고친 파일을 올려 주세요."
- **여백 안내는 결과를 건넬 때마다 빠짐없이** 덧붙인다(사용자 요청 2026-11-03): build.py 출력의 `## 사용자에게 전할 말` 줄(이 문서의 실제 여백과 "온나라 공문에 붙여 넣으실 때는 [쪽] → [편집 용지]에서 왼쪽·오른쪽 여백을 ○·○mm로" 안내)을 그대로 옮긴다. 본문 폭이 같아야 도구가 맞춘 줄 바꿈이 그대로 간다. 위·아래 여백은 온나라 서식마다 달라 쪽 끝은 바뀔 수 있으니 쪽 끝은 붙여 넣은 뒤 확인하시라고 함께 적는다.
- JSON·XML·run 같은 개발 용어는 쓰지 않는다. 존댓말로 답한다.
- 머리말·꼬리말의 글은 견본 것이 그대로 남는다. 견본 머리말에 다른 부서·날짜가 있으면 알린다.

## 아직 못 하는 것(사용자에게 한글에서 하도록 안내)

- 견본에 없는 글꼴·크기·색 만들기 — 그런 모양이 필요하면 견본에 그 모양 문단을 하나 넣어 다시 올려 달라고 한다
- 표 밖에 그림 넣기(표 칸 배경 그림은 됨, 표지의 대구시 마크·슬로건은 기본 양식에 들어 있음), 머리말·꼬리말 글 바꾸기
- 둘째 구역 이후(가로 쪽 등)를 따로 살리기 — 결과는 첫 구역 설정으로 한 구역이 된다
- 표 칸 안 문단의 자간 맞춤(표는 글자 크기 10~12pt·칸 너비 맞춤과 '한 줄로 입력', 옆 열에 폭을 내준 칸의 자간 -9%까지만 한다)
- 한 칸에 쉼표로 이은 여러 내용을 `· 항목` 줄로 바꾸기 — 글을 쓰는 단계(계획 파일)에서 나눈다
