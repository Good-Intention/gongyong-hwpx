# 공무원 한글문서 편집스킬 (HWPX)

호출명 `/gongyong-hwpx`. 견본 한글 파일의 문단을 **복사해서 글만 바꿔 끼운다** — 여백·글꼴·간격·표 모양이 견본과 같고, 견본에 없는 글꼴·크기·색은 생기지 않는다. 자간·줄 간격·칸 너비·쪽 나눔은 사용자 원칙대로 도구가 맞춘다.

| 파일 | 하는 일 | 언제 읽나 |
|---|---|---|
| `scripts/analyze.py` | 견본의 여백과 문단마다 번호·역할·서식·글(양식 지도) | 견본이 있을 때 실행 |
| `scripts/build.py` | 계획 파일대로 만들고 자동 맞춤·검사 | 늘 실행 |
| `scripts/review.py` | 이미 쓴 파일을 바꾸지 않고 검사만 | 7절 |
| `scripts/check.py` | 만든 파일의 구조만 검사 | 필요할 때 |
| `assets/basic_report.hwpx` | 견본이 없을 때 쓰는 기본 양식 | 번호표는 `references/basic-report-map.md` |
| `references/style-guide.md` | **글·짜임·표기·표·쪽 배치 원칙** | **글을 쓰기 전에 반드시** |
| `references/plan-format.md` | 계획 파일 문법 | 계획 파일을 쓸 때 |
| `references/auto-fit.md` | 도구가 맞추는 방법 | 알림 뜻이 궁금할 때만 |
| `references/history.md` | 규칙이 생긴 날짜·사용자 말 | 규칙이 헷갈릴 때만 |

- 파이썬과 lxml이 필요하다(`pip install lxml`). 경로는 이 스킬 폴더 기준(`python <스킬폴더>/scripts/…`). `/mnt/user-data/…`는 Claude 앱 기준이고 다른 앱에서는 그 앱의 올린 파일·결과 폴더.
- **파이썬을 돌릴 수 없는 앱**(코드 실행이 꺼진 ChatGPT·Gemini 등)에서는 한글 파일을 만들지 못한다. 그때는 style-guide.md대로 글을 기호(□ ○ - · ※)째 써 주고 한글에 붙여 넣게 안내하며, 글 끝에 6절의 여백 안내를 그대로 적는다.

## 1. 견본 정하기

- 사용자가 올린 `.hwpx`가 견본이다. `.hwp`(옛 형식)는 읽을 수 없다 — "한글에서 [파일]→[다른 이름으로 저장]→파일 형식 'HWPX'로 저장해 올려 주세요".
- 견본이 없으면 `assets/basic_report.hwpx`. 2절 대신 `references/basic-report-map.md`를 본다.
- **사용자가 결과를 고쳐 다시 올리면 그 파일이 새 견본이다.** 고친 것을 되돌리지 않고, 무엇을 왜 고쳤는지 살펴 다음 문서에도 반영한다.
- 견본에 덮어쓰지 않는다. 결과는 늘 새 이름으로.

## 2. 양식 읽기 — 여백 먼저

```
python scripts/analyze.py 견본.hwpx          # 양식 지도(맨 위가 '여백 먼저')
python scripts/analyze.py 견본.hwpx --text   # 글만 처음부터 끝까지
```

1. **여백 먼저**: 본문 폭·높이, 문단 왼쪽 여백·내어쓰기, 표 폭이 본문과 맞는지(끝선 맞음 / 튀어나옴).
2. **문단 목록**: `[번호]`가 계획 파일의 `like`. 역할(장 제목·□·○·-·*·※·표·빈 줄·참고 머리표)은 기호와 정렬로 짐작한 것이니 글과 서식을 보고 확인한다. `조각N cX …`는 한 문단 안 글 조각의 모양(굵은 이름표, 위 첨자 등).
3. `--text`로 글을 읽고 **견본의 글버릇**(끝맺음·기호 앞뒤 빈칸·날짜·단위·괄호 이름표)을 그대로 따른다.

## 3. 내용 정리 — style-guide.md대로

`references/style-guide.md`를 읽고 짜임(3절)·문장과 표기(4절)·표(5절)를 맞춘다. 특히: 요약 상자는 결론 한 문장, **근거법령은 1번이고 법령 이름·조항만**, 항목은 셋쯤(2~5), 작대기 위주, 본문 표에는 ■ 제목, 참고1은 조문 발췌.

- **사실·숫자·이름은 사용자가 준 것만.** 모르는 값은 `○○`·`○○○원` 자리표시로 두고 전달할 때 알린다. 견본 속 예시 문장·사람 이름·연락처는 옮기지 않는다.
- **근거를 지어내지 않는다.** 법령 검색 도구로 이름·조문을 확인한 법령만(훈령·예규·고시·지침은 행정규칙 검색). 확인 못 하면 `「○○법」 제○조`로 비워 두고 알린다. 참고1 발췌는 원문 조문을 글자 하나 바꾸지 않고 옮긴다.
- 꼭 필요한데 빠진 것(제목, 보고 날짜, 부서)은 짧게 한 번에 묻는다. 내용이 분명하면 묻지 말고 바로 만든다. 날짜·부서를 모른 채 만들면 그 줄을 빼지 말고 ○로 채운다.
- **내용이 거의 없으면 질문으로 모은다(근거법령부터)**: 한 번에 한 주제, 번호 선택지로 묻고 고른 번호를 받는다(사용자가 고치면 그대로). 차례: 근거법령 → 추진배경 → 현황 → 주요내용 → 확산·운영 → 일정 → 예산 → 기대효과 → 행정사항·날짜·부서. 근거법령 후보는 원문 조문을 확인한 것만(조문 번호·요지). 숫자·기관 사정처럼 확인할 수 없는 것은 "맞을 때만 고르라"고 밝히고 답이 없으면 ○○로 비운다. 답은 작업 폴더의 기록 파일에 차례로 적어 둔다.

## 4. 계획 파일 쓰기

블록 하나가 문단(또는 표) 하나. 문법은 `references/plan-format.md`.

```json
{"title": "공원 안내판 정비 계획(안)",
 "blocks": [
  {"like": 0, "text": "공원 안내판 정비 계획(안)"},
  {"like": 6, "text": "추진배경"},
  {"like": 7, "text": "**(현황)** 노후 시설이 29곳^^*^^으로 야간 시인성이 떨어짐"},
  {"like": 8, "text": "노후 시설: 설치 후 10년이 지난 안내판"},
  {"like": 14, "title": "안내판 개선 내용", "unit": "(단위 : 곳)", "table": [["구  분", "현  행"], ["표지판", "일반 도색"]]}
 ]}
```

## 5. 만들고 검사하기

```
python scripts/build.py --template 견본.hwpx --plan plan.json --out 결과.hwpx
```

도구가 저절로 하는 일은 style-guide.md의 "(도구)" 항목 전부다(글 모양·표·쪽·근거법령 자리). 출력은 두 등급:

- **## 고쳐야 함** — 전하기 전에 계획을 고쳐 다시 만든다: 근거법령 없음·하나뿐·부연설명, ‘~으로’ 끝맺음, 한 열에 세 가지 정보, 요약 상자(번호·여러 항목·끝맺음), 표 제목 없음·긴 제목, 날짜 줄 없음, 끝 줄에 한두 낱말만 남은 문단, 항목 수(하나뿐·다섯 넘음), 두 쪽에 걸친 □ 묶음, 칸보다 긴 낱말, 줄여도 넘어가는 칸, 빈칸이 크게 벌어지는 줄, 견본 기호와 다른 기호·굵은 조각 없음(대개 `like` 잘못), 검사 '문제 있음'·'좁은 칸'.
  - **'한 줄 줄이기 후보(약 N자)'**: 그 문단에서 없어도 되는 낱말 하나(조사, 위 제목이 말해 주는 말, 꾸밈말, `와`→`·`)를 빼고 다시 만든다. N자는 자간을 최대로 줄인 기준이라 한두 자 더 빼면 덜 빽빽하다. 반대로 줄이 휑하거나 쪽이 비면 뜻을 바꾸지 않는 낱말·줄 하나를 더한다.
- **## 알림(참고)** — 도구가 한 일의 기록. 읽고 넘어가되 **어림 쪽 수와 쪽마다 채운 비율은 꼭 본다**: 마지막 쪽이 거의 비었거나 쪽 수가 예상과 다르면 내용을 줄이거나 나눈다. **'순서 바꾸기를 검토하세요'**는 뜻·흐름이 그대로일 때만 계획에서 두 □ 순서를 바꿔 다시 만든다.
- **글 차례**를 처음부터 끝까지 읽어 빠진 내용·오탈자·자리표시를 확인한다. Claude 앱에서는 결과를 `/mnt/user-data/outputs/`에 두고 파일 이름은 문서 제목으로.
- 줄·쪽은 한글 없이 어림한 것이다(한글 2024와 맞댄 시험 문서 15개 — 105쪽 문서 둘 포함 — 에서 쪽 수는 모두, 글 문단 줄 바꿈은 3,482개 중 3,481개가 같았다). 표에 없는 글꼴은 덜 정확하다. 마지막 확인은 한글에서.

## 6. 전달하기

- 결과 파일을 건네고 쉬운 말로 3줄 안팎: 어떤 양식으로 만들었는지, 자동으로 맞춘 것, 채워야 할 자리표시, "한글에서 열어 보시고 고칠 곳을 말씀하시거나 고친 파일을 올려 주세요."
- **여백 안내는 결과를 건넬 때마다**: build.py 출력의 `## 사용자에게 전할 말`(이 문서의 실제 여백과 "온나라 공문에 붙여 넣으실 때는 [쪽] → [편집 용지]에서 왼쪽·오른쪽 여백을 ○·○mm로")을 그대로 옮긴다. 본문 폭이 같아야 줄 바꿈이 그대로 간다. 위·아래 여백은 온나라 서식마다 달라 쪽 끝은 붙여 넣은 뒤 확인하시라고 함께 적는다. 기본 양식은 A4, 본문 칸 사방 20mm.
- JSON·XML·run 같은 개발 용어는 쓰지 않는다. 존댓말. 머리말·꼬리말 글은 견본 것이 그대로 남으므로 다른 부서·날짜가 있으면 알린다.

## 7. 이미 쓴 문서 검사만

사용자가 **이미 쓴 한글 파일**을 주며 "검사해 줘", "서식 봐 줘", "원칙에 맞는지 봐 줘"라고 하면(새로 쓰라는 말이 없으면) 다시 만들지 말고 **검사만** 한다 — 파일을 바꾸지 않는다.

```bash
python scripts/review.py 문서.hwpx        # 표가 많아 느리면 --no-tables
```

- 결과를 그대로 옮긴다: 어림 쪽 수·여백 → **고쳐야 함**(글·짜임 — 작성자가 정할 것) → **다듬기가 고칠 것**(다듬기를 한 번 걸어 보고 실제로 바뀌는 것만. 이 도구로 만든 문서는 '없음'이 정상) → 참고(쓰인 글꼴).
- 고쳐 달라고 하면: 글·짜임은 사용자가 정한 대로 계획 파일을 새로 써서 만들고(견본 = 그 파일), 서식만 고치는 다듬기는 아직 없다고 말한다.
- 견본과 다른 짜임(□○ 없는 서술식 등)은 알림이 비거나 어긋날 수 있다.

## 아직 못 하는 것(한글에서 하도록 안내)

- 견본에 없는 글꼴·크기·색 — 필요하면 견본에 그 모양 문단을 하나 넣어 다시 올려 달라고 한다.
- 표 밖에 그림 넣기(표 칸 배경 그림은 됨, 표지 마크·슬로건은 기본 양식에 있음), 머리말·꼬리말 글 바꾸기.
- 둘째 구역 이후(가로 쪽 등) 살리기 — 결과는 첫 구역 설정으로 한 구역이 된다.
- 표 칸 안 문단의 자간 맞춤(표는 글자 크기·칸 너비·'한 줄로 입력', 폭을 내준 칸 -9%까지만).
- 한 칸에 쉼표로 이은 여러 내용을 `· 항목` 줄로 바꾸기 — 계획 파일에서 나눈다.
