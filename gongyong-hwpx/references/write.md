# 작성 — 견본부터 검사까지

> 한 주제 = 한 파일 한 곳 — 이 파일은 작성 순서만.

도구: `scripts/analyze.py`(견본의 양식 지도) · `scripts/build.py`(만들기·자동 맞춤·검사) · `assets/basic_report.hwpx`(기본 양식).

## 1. 견본 정하기

- 사용자가 올린 `.hwpx`가 견본이다. `.hwp`(옛 형식)는 읽을 수 없다 — "한글에서 [파일]→[다른 이름으로 저장]→파일 형식 'HWPX'로 저장해 올려 주세요".
- 견본이 없으면 `assets/basic_report.hwpx` — 2절은 건너뛴다(기호로 쓰므로 번호표도 보지 않음).
- **사용자가 결과를 고쳐 다시 올리면 그 파일이 새 견본이다.** 고친 것을 되돌리지 않고, 무엇을 왜 고쳤는지 살펴 다음 문서에도 반영한다.
- 견본에 덮어쓰지 않는다. 결과는 늘 새 이름으로.

## 2. 양식 읽기(견본이 있을 때) — 여백 먼저

```
python scripts/analyze.py 견본.hwpx          # 짧은 양식 지도
python scripts/analyze.py 견본.hwpx --text   # 글만 처음부터 끝까지
```

두 명령을 한 번에 돌려 함께 읽는다.

1. **여백 먼저**: 본문 폭·높이, 본문 폭과 다른 표가 있는지.
2. **'기호로 쓰기' 목록**이 이 견본에서 쓸 수 있는 기호다(없는 기호는 쓰지 않음). 상자·그림처럼 기호가 없는 문단은 '번호로 쓰는 문단'의 번호로.
3. `--text`로 **견본의 글버릇**(끝맺음·날짜 줄 꼴·단위·괄호 이름표)을 익혀 그대로 따른다.

## 3. 내용 정리

- style-guide대로 짜임(2절)·문장과 표기(3절)·표(4절)를 맞춘다. 첫 만들기에서 가장 자주 걸리는 것: **□마다 ○는 2~5개**(하나뿐이면 둘로 나누거나 다른 □와 합침), **본문 표에는 ■ 제목**, 요약 상자 끝맺음, 근거법령 ○ 둘 이상.
- **근거법령은 1번, ○ 하나에 법령 하나, 확인된 것만** — 세부는 style-guide 2-1.
- **사실·숫자·이름은 사용자가 준 것만.** 모르는 값은 `○○`·`○○○원` 자리표시로 두고 전달할 때 알린다. 견본 속 예시 문장·사람 이름·연락처는 옮기지 않는다. 사용자 말에 없는 것(연도·요일·합계)을 덧붙였으면 전달할 때 밝힌다.
- 꼭 필요한데 빠진 것(제목, 보고 날짜, 부서)은 짧게 한 번에 묻는다. 내용이 분명하면 묻지 말고 바로 만든다.
- **내용이 거의 없으면 질문으로 모은다(근거법령부터)**: 한 번에 한 주제, 번호 선택지로 묻고 고른 번호를 받는다(사용자가 고치면 그대로). 차례: 근거법령 → 추진배경 → 현황 → 주요내용 → 확산·운영 → 일정 → 예산 → 기대효과 → 행정사항·날짜·부서. 근거법령 후보는 원문 조문을 확인한 것만(조문 번호·요지). 숫자·기관 사정처럼 확인할 수 없는 것은 "맞을 때만 고르라"고 밝히고 답이 없으면 ○○로 비운다. 답은 작업 폴더의 기록 파일에 차례로 적어 둔다.

## 4. 계획 파일 쓰기

plan-format대로 기호로 쓴다 — 블록 하나가 문단(또는 표) 하나.

## 5. 만들고 검사하기

```
python scripts/build.py --template 견본.hwpx --plan plan.json --out 결과.hwpx
```

출력 둘째 줄 `## 한눈에: 고쳐야 함 N건, …`부터 본다. 끝 번호 0은 고칠 것 없음, **3은 파일은 만들었으나 '고쳐야 함'이 남음**, 1은 구조 검사 문제(그 파일은 전하지 않음).

- **## 고쳐야 함** — 전하기 전에 계획을 고쳐 다시 만든다. 무엇을 어떻게 고칠지는 출력 문장에 있다.
  - **다시 만들기는 두 번까지**: 두 번 고쳐 다시 만들어도 남는 것은 무엇이 왜 남았는지 한 줄씩 알리고 그대로 건넨다. 고치며 다시 만들 때는 `--brief`(글 차례 생략)를 붙여도 되고, 전하기 전 마지막 판은 `--brief` 없이 만들어 글 차례를 읽는다.
  - **'한 줄 줄이기 후보(약 N자)'**: 그 문단에서 뜻·숫자·날짜·이름·법령을 바꾸지 않는 낱말 하나(조사, 위 제목이 말해 주는 말, 꾸밈말, `와`→`·`)를 빼고 다시 만든다. N자는 자간을 최대로 줄인 기준이라 한두 자 더 빼면 덜 빽빽하다. 반대로 줄이 휑하거나 쪽이 비면 뜻을 바꾸지 않는 낱말·줄 하나를 더한다.
- **## 알림(참고)** — 도구가 한 일의 기록이라 훑고 넘어간다. **쪽 수와 쪽마다 채운 비율만 꼭 본다**(`한눈에` 줄에도 있음): 마지막 쪽이 거의 비었거나 쪽 수가 예상과 다르면 내용을 줄이거나 나눈다. **'순서 바꾸기를 검토하세요'**는 뜻·흐름이 그대로일 때만 계획에서 두 □ 순서를 바꿔 다시 만든다.
- **## 수치·맞춤법 확인** — 고치지 않고 결과와 함께 그대로 알린다(내 셈이 틀렸으면 계획을 고침). 사용자가 준 원자료의 숫자와도 맞대어 다르면 알린다.
- **글 차례**를 처음부터 끝까지 읽어 빠진 내용·오탈자·자리표시를 확인한다. Claude 앱에서는 결과를 `/mnt/user-data/outputs/`에 두고 파일 이름은 문서 제목으로.

## 환경

- `/mnt/user-data/…`는 Claude 앱 기준(다른 앱은 그 앱의 올린 파일·결과 폴더).
- 코드를 돌릴 수 없는 앱(코드 실행이 꺼진 ChatGPT·Gemini 등)에서는 한글 파일을 못 만든다 — style-guide대로 글을 기호(□ ○ - · ※)째 써 주고 붙여 넣게 안내하며, 끝에 여백 안내(온나라 [쪽] → [편집 용지]에서 왼쪽·오른쪽 여백을 견본과 같게, 기본 양식 20·20mm)를 적는다.

## 아직 못 하는 것(한글에서 하도록 안내)

견본에 없는 글꼴·크기·색(그 모양 문단을 견본에 넣어 다시 올려 달라고 함) · 표 밖 그림(표 칸 배경 그림·기본 양식 표지 마크·슬로건은 됨)과 머리말·꼬리말 글 바꾸기 · 둘째 구역 이후(가로 쪽 등 — 첫 구역 설정으로 한 구역이 됨) · 표 칸 안 자간 맞춤(표는 글자 크기·칸 너비·'한 줄로 입력', 폭을 내준 칸 -9%까지만) · 쉼표로 이은 칸 글을 `· 항목` 줄로(계획에서 나눔).
